# 記事取得APIの修正（2026-11-04）

## 確認できたこと

ユーザーの「記事取得サーバーに接続できません」という表示は、従来のクライアントでは非JSON応答を受けた際に一律表示していた文言。公開先の404・起動エラー・アクセス制限等を判別できなかった。実際の公開先が返したHTTPステータスとログは未取得であり、note側の拒否やURL rewriteだけが原因だったと断定しない。

この作業環境から `https://gpt-delta.vercel.app/api/article` への確認は、環境のHTTPプロキシのCONNECT段階で403拒否された。この403は公開サイトやnoteの応答ではない。

## 変更

- `/api/article` → `/api/index` のrewriteを廃止し、`api/article.js` を直接配置。
- Vercelの入口からExpressアプリへの依存を除去。記事取得ロジックを `lib/article.js` に移し、依存ライブラリはPOST時に読み込む。起動失敗も可能な範囲でJSONの503として返す。
- ローカルサーバーも同じハンドラーを使用。プライベートIP拒否、リダイレクト検証、本文サイズ上限を維持。
- GETは入口のバージョン確認用。外部サイト到達・本文取得の成功は保証しない。
- 非JSONの404、401/403、500系、504と、記事側のJSONエラーを別々に表示。
- 失敗時に文章貼り付け・画像取り込みへ移れるボタンを追加。

## 検証と限界

ビルド成功、ユニット・HTTPテスト18件、ブラウザテスト5件が成功。Vercel形式のハンドラー、依存読み込み失敗、URL入力、プライベートIP拒否、非JSON応答、エラー後の代替入力、正常応答時の読書画面を検証した。成功応答・起動失敗・公開404はテスト用の再現であり、実際のnote記事の取得成功を確認したものではない。

公開環境でのデプロイ完了とnote記事の取得成功は、環境の接続制限により未確認。VercelのRoot Directoryがリポジトリルート以外でAPIファイルを除外している場合等は、ダッシュボード側の修正も必要となる。
