# OCRの改善実装 — 2026-11-04

前回の独立エージェントによる設計レビューを踏まえ、今回は実装を点検して改善した。今回の実装は別エージェントによる再評価ではなく、実コードの確認、ユニットテスト、ブラウザテストで検証した。

## 見つけた問題と変更

1. 画像ごとにOCRエンジンを生成・終了していた。セッション内で再利用し、未使用60秒、待機中のバックグラウンド移行、ページ離脱で解放する。
2. 認識開始までの工程が見えなかった。画像準備、モデル読み込み、初期化、文字認識の進捗・経過秒と、完了後の工程別時間を表示する。
3. 全画面を読み取っていた。元解像度を保って、指定した上下左右の範囲だけを1回OCRする。範囲は画像に重ねて表示し、画像全体へ戻せる。
4. 認識率だけで自動再生していた。結果の確認・編集後に再生する。修正前のOCR結果へ戻すボタンを追加した。
5. 元画像が読書画面から参照しづらかった。図・写真・表を含む画像全体をモーダルで拡大できるようにし、読む位置を維持して一時停止する。別の文章に切り替えたときは元画像との関連を解除する。
6. エンジン再利用で生じる競合への対策。処理の重複を拒否し、中止された処理の進捗・結果を反映しない。初期化中の中止は画像認識を停止し、初期化自体は次の処理で共有する。認識中の中止・失敗はエンジンを解放して再試行できるようにした。処理には120秒のタイムアウトを設けた。

- Chromiumのブラウザテスト4件成功。最後の中止テストはtextareaの検証方法を修正して単独で再実行。

- OCR結果を勝手に再生しないこと、編集の取り消し、元画像参照・拡大・閉じた後の位置維持、別文章への切り替えを確認。
- モデル読み込みを意図的に遅らせ、中止→再試行でWorkerが重複しないことを確認。
- 外部サービスへ画像を送信していないことをブラウザのリクエストで確認。

## 残る制約

Android実機での速度・メモリ測定は未実施。今回の検証はクラウド上のデスクトップChromiumであり、スマホで何倍速くなるという主張はしない。初回のダウンロード・初期化、文字認識の処理時間は残る。モデルの軽量版への切り替えは精度比較前のため実施しない。

本文範囲は手動指定。自動的な本文・広告の判別、図と本文の自動対応付け、図の説明生成、他アプリの自動スクロールは今回の実装に含めない。図の意味を文字だけで補完せず、元画像を参照する。画像内にない別ページの図は表示できない。

完了時の所要時間にはファイル選択・範囲指定・結果確認の操作時間は含まない。初回から読書開始までの総時間の評価は今後の実機計測に含める。
